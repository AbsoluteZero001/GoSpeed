# GoSpeed 路线图

路线图描述方向，不代表承诺。任何版本发布前都必须满足同一套真实性与测试要求：
不使用模拟数据、不输出未采集指标、`go test ./...` 与 `go test -race ./...` 全绿。

## v0.1.0（已实现）

- 项目初始化与模块化架构
- CLI：`test` / `server` / `nodes` / `version`
- 本地 HTTP 测速服务器：`/health`、`/ping`、`/download`、`/upload`
- HTTP RTT 延迟测试、单连接下载 / 上传（真实字节计数、服务端确认）
- 结构化 JSON 结果与基础单元测试、GitHub Actions CI

## v0.2.0（已实现）

- 多连接并发下载 / 上传（1..16，端到端覆盖 1 / 4 / 8 / 16）
- 共享字节预算与统一测量窗口，连接级报告（`connection_reports`）
- 部分连接失败告警、全部失败报错
- 实时速率采样（默认 200 ms）与描述性统计（平均 / 中位 / 最小 / 最大 / n-1 标准差 / CV）
- TTY 动态进度条与普通文本降级；JSON 模式 stdout 纯净

## v0.3.0 当前版本（已实现）

Multi-Node Speed Testing & Network Validation

- 多节点管理：`list` / `check` / `auto` / `add` / `remove` / `enable` / `disable`
- 节点配置 JSON：唯一 ID 校验、地址策略校验、原子写入（临时文件 + rename）
- 健康检测：DNS / TCP / TLS / HTTP 状态分段计时，有限重试，状态
  `healthy` / `degraded` / `unavailable` / `unknown`
- 节点能力协商：`GET /capabilities`（协议版本、服务端版本、能力列表、限额），
  旧服务端（404/405）标记为 legacy 并继续可用
- 自动选择：先可用性、再实测 HTTP RTT 中位数、最后稳定 ID；
  选择原因与候选排名写入结果；仅用于挑选候选节点，不代表带宽排名
- 真实远程 HTTP(S) 测速：默认校验证书、支持连接超时与取消、不跳过 TLS 校验
- 客户端在开始前校验服务端公布的连接数 / 时长 / 字节限额，超限直接报错（不静默裁剪）
- 多次测速：`--repeat N` 顺序执行，每次保留独立 `Result`，另生成 `Summary`
  （仅聚合已完成运行；不同节点 / 连接数 / 时长绝不混合）
- 结果可信度：网络范围（local / lan / remote / unknown）、选择方式、
  节点健康与能力信息写入结果
- 服务端安全：并发测速上限（超出返回 503 + Retry-After）、每请求字节与时长上限、
  默认仍只监听 `127.0.0.1`

## v0.4.0 本地 Web UI 与结果浏览

- 本地 Web 界面（仪表盘式布局，高信息密度、低装饰）
- 实时速率曲线（消费现有 `samples` 与 `Progress` 事件）
- 节点选择界面、节点健康表与能力信息展示
- 历史结果浏览与 JSON / CSV 导出
- 四分位（P25 / P75 / IQR）与连接数对比视图

## v0.5.0 桌面客户端

- Wails + Vue 3 + TypeScript 桌面应用
- Windows 桌面安装包
- 深色 / 浅色主题
- 历史结果可视化

## v0.6.0 跨平台与诊断

- Linux / macOS 桌面支持
- 网络接口状态显示（协商速率与吞吐量严格区分，未知时显示 `N/A`）
- 更完整的网络诊断能力

## 公网部署与配额（预留，尚未实现）

以下能力目前**尚未实现**，文档不得声称已经具备：

- 节点身份验证 / 授权（token、mTLS）
- 全局流量配额与单客户端配额（按字节计费，而不是只按请求次数限流）
- 节点侧监控指标、日志聚合与告警
- 官方公共测速节点清单
- 多节点并行对比测速（当前 `--auto` 只选一个节点）

当前已实现的服务端保护是：并发测速上限、单请求上传 / 下载字节上限、
单请求时长上限、HTTP 读写超时，以及默认只监听回环地址。

## 未来版本

- ICMP / UDP 网络质量测试（真实丢包率）
- 负载延迟（loaded latency）与 Bufferbloat 分析
- 多节点测速网络与结果聚合
- 持续网络监控与告警

## 明确不做的事

- 不伪造任何测速数字；
- 不对 Mbps 乘任何“接近商业工具”的补偿系数；
- 不把网卡协商速率当作实测吞吐；
- 不把 HTTP 请求失败率当作丢包率；
- 不把节点延迟排名解释为服务器带宽排名；
- 不在没有真实数据时显示 `0`、`0%` 或“正常”状态。
