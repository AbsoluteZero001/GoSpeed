# 测速原理与准确性说明

GoSpeed 的目标是让每个数字都能被解释、被复现、被质疑时查得清楚。
v0.2.0 在单连接的基础上增加了多连接并发、实时采样与描述性统计，
本文档说明这些数字各自的口径。

## 计算方式

```text
Mbps = bytes × 8 / seconds / 1,000,000
```

单位约定：

| 单位 | 含义 | 是否使用 |
| --- | --- | --- |
| Mbps | 每秒百万比特（10^6 bit） | 默认展示 |
| MB/s | 每秒百万字节（10^6 byte） | 辅助展示 |
| MiB/s | 每秒 2^20 字节 | 仅用于字节量展示 |
| Gbps | 每秒十亿比特 | 仅在链路速率语境中使用 |

网卡协商速率（例如 1.0 Gbps）与实际吞吐量（例如 936 Mbps）是两个不同指标。
GoSpeed 不读取网卡速率，也不会把它当作测速结果。

## 各阶段测量定义

### HTTP RTT（延迟）

- 端点：`GET /ping`，服务端返回 `204 No Content`。
- 采样：默认 5 次，间隔 100 ms；每个样本独立计时。
- 定义：发送请求到收到第一个响应字节的时间，使用单调时钟测量。
- 预热：开启 `--warmup` 后先请求一次 `/health`，DNS 与 TCP/TLS 握手不计入样本。
- 输出：`min`、`max`、平均值，以及相邻样本差值的平均绝对值（HTTP RTT jitter）。
- **这不是 ICMP ping**。结果中的 `latency.type = http_rtt` 明确标注类型。

### 下载

1. 请求 `GET /download?duration_ms=...`（或 `bytes=...`）。
2. 服务端持续写入不可压缩的随机数据块。
3. 客户端用固定 64 KiB 缓冲区流式读取并计数，不整块加载到内存。
4. 测量窗口：
   - 单连接：第一个响应字节 → 传输停止；
   - 多连接：所有连接中最早的第一个响应字节 → 聚合传输停止。
5. 按时长测试时窗口在统一的时长截止点结束，因此窗口内的停顿会降低结果而不是被隐藏；
   按字节测试时窗口在最后一个数据字节结束。
6. 服务端提前关闭连接会被判定为失败，而不是输出半截速率。

### 上传

1. 客户端用 `crypto/rand` 生成一个 256 KiB 随机块，循环流式发送（chunked）。
2. 服务端 `io.Copy(io.Discard, body)` 统计实际收到的字节数并返回确认。
3. 客户端必须等到确认后才计算速率，发送任务创建成功不等于上传完成。
4. 校验：客户端发送字节数必须等于服务端确认字节数，否则返回
   `ErrByteCountMismatch`，不输出结果。
5. 测量窗口：
   - 单连接：第一次写请求体 → 该连接的服务端确认读完；
   - 多连接：最早一次写请求体 → 最后一个服务端确认读完。
6. 窗口故意包含确认等待的往返时间，属于偏保守的定义；
   结果字段 `measurement_window` 会明确标注这一点。

### 丢包

v0.2.0 **没有** UDP/ICMP 丢包测试能力：

- `latency.packet_loss_percent` 永远输出 `null`（显示为 `N/A`）；
- HTTP 请求失败率不会被标记为网络丢包率；
- 只有实现真实的数据包级测试后，该字段才会被填充。

## 实时采样与统计

### 采样点

- 默认每 200 ms 采样一次，可用 `--sample-interval` 修改。
- 每个采样点包含：阶段、UTC 时间戳、单调时钟 elapsed、累计字节、
  当前区间 Mbps、窗口平均 Mbps、活跃连接数。
- 当前区间 Mbps 使用**两次真实观测之间**的单调时钟差值计算，
  不使用标称采样间隔；ticker 迟到不会把速率算错。
- 采样不足时统计字段为 `null`（N/A）：0 个采样点没有统计，
  1 个采样点没有标准差与变异系数。
- 慢的进度消费者只会让部分采样点被合并（丢弃过期 tick），
  最终速率来自原子计数器和真实窗口，不受采样丢弃影响。

### 统计口径

对采样点的 `current_mbps` 计算：

| 指标 | 定义 |
| --- | --- |
| 平均值 | 算术平均 |
| 中位数 | 排序后中间值（偶数个取中间两个平均） |
| 最小值 / 最大值 | 采样极值 |
| 标准差 | 样本标准差（n-1），`stddev_kind = sample_n_minus_1` |
| 变异系数 | 标准差 / 平均值 × 100%，平均值 ≤ 0 时不计算 |

三个“平均值”必须区分：

1. **瞬时吞吐量**：采样点的 `current_mbps`（区间速率）；
2. **测试窗口平均吞吐量**：结果里的 `mbps`（整个窗口的字节总和 / 窗口时长）；
3. **多次测速平均吞吐量**：v0.2.0 尚未实现（历史记录在 v0.3.0），
   不能把单次窗口平均值当成多次结果的平均值。

采样波动小 **不等于** 结果绝对准确；它只说明测试窗口内速率相对稳定。
GoSpeed 不使用这种波动去评价“网络质量优秀 / 较差”。

## 多连接并发说明

- 连接数范围 1..16，端到端测试覆盖 1 / 4 / 8 / 16。
- `--max-bytes` 是整个阶段的共享字节预算：1 连接和 16 连接下载的总字节数
  相同，不会随连接数放大。
- 所有连接共享同一个测量窗口，窗口起始取“最早出现数据的连接”，
  窗口结束按前面各阶段的定义；**不会把各连接的时间或 Mbps 相加**。
- 每个连接的结果都记录在 `connection_reports` 中（状态、字节数、
  上传时还有服务端确认字节数与错误信息），聚合值必须等于逐连接之和。
- 部分连接失败时仍然给出结果，但会带 `warnings`，
  并记录 `active_connections` / `failed_connections`；吞吐量只代表实际参与的连接。
  全部连接失败则直接报错，不输出 Mbps。
- **连接越多不一定越准确**：并发会同时放大客户端 CPU、服务器容量、
  中间设备队列与拥塞控制的影响；不同连接数的结果应该对比而不是互相替代。
  建议至少比较 1 与常用值（4 / 8）后再决定对外报告哪个口径。

## 节点选择与延迟排序

`gospeed nodes auto` 使用真实探测数据排序节点，口径固定：

1. `healthy` 优先于 `degraded`，`unavailable` 节点不参与排名；
2. 同状态下比较 `/ping` 采样的 HTTP RTT 中位数（可配置采样次数）；
3. 仍然并列时按节点 ID 升序，并在选择原因中明确写出“并列”。

**延迟最低不代表吞吐量最高**。自动选择只用于挑选一个候选测速节点，
不代表服务器带宽排名，也不能替代真实下载 / 上传测速。GoSpeed 在
`Selection.Note` 和 CLI 输出中都会声明这一点。

健康探测的分段指标口径：

| 指标 | 口径 |
| --- | --- |
| DNS | `DNSStart` 到 `DNSDone`；IP 字面量不触发，显示 N/A |
| TCP Connect | `ConnectStart` 到 `ConnectDone` |
| TLS Handshake | `TLSHandshakeStart` 到 `TLSHandshakeDone`；仅 HTTPS |
| HTTP RTT | 请求开始到第一个响应字节 |

这些指标互不替代：TCP Connect 时间不是 ICMP Ping，HTTP RTT 也不是 ICMP Ping。
平台时钟无法分辨的极短阶段读数为 0，表示低于时钟分辨率(N/A)；
延迟采样中这类样本会被单独计数，不会伪装成 0.00 ms。

## 多次测速与统计口径

`gospeed test --repeat N` 顺序执行 N 次完整测试，每次保留独立的 `Result`，
再由 `Summary` 聚合：

- 只有 `completed` 运行进入 Download / Upload / HTTP RTT / Jitter 统计；
  `failed` 与 `cancelled` 运行会被计数并保留明细，但不贡献数值；
- 标准差为样本标准差（n-1），变异系数 = 标准差 / 平均值 x 100%；
- 单次运行内部还有一层采样统计（200 ms 采样点），两层统计不要混淆：
  `Result.statistics` 描述一次测试内部的波动，`Summary.*` 描述多次测试之间的波动；
- 目标节点、连接数、时长或字节预算不同的运行会被 `ErrMixedConditions` 拒绝，
  绝不会被合并成同一个“平均值”；
- 重复次数有上限（10），因为每一次运行都会消耗真实的公网流量。

## 测量注意事项

1. **单调时钟**：所有耗时都通过 `time.Now()`/`time.Since()` 获得单调读数，
   系统时钟跳变不会破坏结果。
2. **平台计时精度**：Windows 等平台的时钟分辨率有限，回环环境下极短传输可能
   读到 0 时长；此时引擎会返回错误（`ErrZeroDuration`），而不是输出 `+Inf`。
3. **缓存与压缩**：客户端与服务端都禁用缓存，客户端关闭透明压缩并声明
   `identity` 编码；服务端发送随机数据，避免被压缩后虚高。
4. **连接建立时间**：下载速率窗口不含 DNS/TCP/TLS；首个延迟样本可能包含，
   预热后样本不再包含。
5. **回环测试不代表公网带宽**：`127.0.0.1` 的结果只反映本机协议栈与进程调度能力，
   CLI 会明确打印 `Local Loopback Test`。
6. **服务器瓶颈**：结果同时受客户端、服务器 CPU、反向代理和链路影响。
   要区分网络瓶颈与服务器瓶颈，请对比多节点结果并观察 `connection_reports`
   是否出现个别连接明显偏低。
7. **禁止补偿系数**：GoSpeed 不会对 Mbps 结果乘以任何经验系数。
8. **服务端限额**：客户端会先协商 `GET /capabilities`，如果请求超过服务端
   公布的连接数 / 时长 / 字节上限，直接报错而不是静默降级为“看起来正常”的结果。

## 如何做重复性与对照验证

```powershell
# 1. 启动本地测试服务器
go run ./cmd/gospeed server

# 2. 同一窗口、同一连接数重复运行
go run ./cmd/gospeed test --connections 4 --duration 10s --json

# 3. 与操作系统工具对照（示例：下载一个固定大小 10 次取中位数）
curl.exe -o NUL -w "%{speed_download}\n" http://127.0.0.1:8080/download?bytes=1073741824
```

对照原则：

- 比较同一时间窗口、同一服务器、同一连接数的结果；
- 至少重复 5 次，使用中位数而不是单次最大值；
- 记录 `test_id`、时间戳、`settings` 与 `connection_reports`，保证可审计；
- 当结果与预期差距很大时，先确认瓶颈在客户端、服务器还是链路，
  再讨论测速工具本身是否准确。

## 误差来源（诚实清单）

| 来源 | 影响 | 当前处理 |
| --- | --- | --- |
| 平台时钟分辨率 | 极短传输可能读数为 0 | 返回错误，不编造速率 |
| 阶段计时分辨率 | DNS/TCP/TLS 可能显示 N/A | 如实标记，不用估算值填充 |
| HTTP 分层开销 | 上传窗口包含一次确认往返 | 明确定义窗口，偏保守 |
| 单连接拥塞控制 | 可能低估链路容量 | 结果标注连接数，支持 1..16 |
| 多连接资源竞争 | 客户端 / 服务器 CPU 可能成为瓶颈 | 记录逐连接数据与告警 |
| 服务器 CPU / 调度 | 高带宽下可能成为瓶颈 | 文档提示，未来支持多节点对比 |
| 代理与缓存 | 可能改变字节流 | `no-store` + `identity` + 禁用压缩 |
| 回环路径 | 不代表公网 | 明确标记为本地回环测试 |
| 节点延迟排序 | 不代表带宽 | 只在候选选择中使用，并明确声明 |
