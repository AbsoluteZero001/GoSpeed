# 测速原理与准确性说明

GoSpeed 的目标是让每个数字都能被解释、被复现、被质疑时查得清楚。

## 计算方式

```text
Mbps = bytes × 8 / seconds / 1,000,000
```

单位约定：

| 单位 | 含义 | 是否使用 |
| --- | --- | --- |
| Mbps | 每秒百万比特（10^6 bit） | 默认展示 |
| MB/s | 每秒百万字节（10^6 byte） | 辅助展示 |
| MiB/s | 每秒 2^20 字节 | 预留 |
| Gbps | 每秒十亿比特 | 仅在链路速率语境中使用 |

网卡协商速率（例如 1.0 Gbps）与实际吞吐量（例如 936 Mbps）是两个不同指标。
GoSpeed v0.1.0 不读取网卡速率，也不会把它当作测速结果；将来读取接口信息时会
单独放在网络状态模块，并允许该字段为 `N/A`。

## 各阶段测量定义

### HTTP RTT（延迟）

- 端点：`GET /ping`，服务端返回 `204 No Content`。
- 采样：默认 5 次，间隔 100 ms；每个样本独立计时。
- 定义：发送请求到收到第一个响应字节的时间，通过 `httptest`/`httptrace` 语义
  与 `time.Now()`/`time.Since()` 单调时钟测量。
- 预热：开启 `--warmup` 后先请求一次 `/health`，DNS 与 TCP/TLS 握手不计入样本，
  后续样本复用同一条连接。
- 输出：`min`、`max`、平均值，以及相邻样本差值的平均绝对值（HTTP RTT jitter）。
- **这不是 ICMP ping**。结果中的 `latency.type = http_rtt` 明确标注类型；
  ICMP 与 TCP Connect 延迟是 v0.2.0 起的独立指标。

### 下载

1. 请求 `GET /download?duration_ms=...`（或 `bytes=...`）。
2. 服务端持续写入不可压缩的随机数据块。
3. 客户端用固定 64 KiB 缓冲区 `io.CopyBuffer` 流式读取并计数，不整块加载到内存。
4. 测量窗口从第一个响应字节开始，到最后一个响应体字节（或客户端取消）结束。
5. 时长窗口到期属于正常结束；服务端提前关闭连接会被判定为失败，而不是输出半截速率。

### 上传

1. 客户端用 `crypto/rand` 生成一个 256 KiB 随机块，循环流式发送（chunked）。
2. 服务端 `io.Copy(io.Discard, body)` 统计实际收到的字节数并返回确认。
3. 客户端必须等到确认后才计算速率，发送任务创建成功不等于上传完成。
4. 校验：客户端发送字节数必须等于服务端确认字节数，否则返回
   `ErrByteCountMismatch`，不输出结果。
5. 速率分子使用服务端确认的字节数，分母使用客户端从首次写体到收到确认的耗时，
   属于偏保守的定义。

### 丢包

v0.1.0 **没有** UDP/ICMP 丢包测试能力：

- `latency.packet_loss_percent` 永远输出 `null`（显示为 `N/A`）；
- HTTP 请求失败率不会被标记为网络丢包率；
- 只有实现真实的数据包级测试后，该字段才会被填充。

## 测量注意事项

1. **单调时钟**：所有耗时都通过 `time.Now()`/`time.Since()` 获得单调读数，
   系统时钟跳变不会破坏结果。
2. **平台计时精度**：Windows 等平台的时钟分辨率有限，回环环境下极短传输可能
   读到 0 时长；此时引擎会返回错误（`ErrZeroDuration`），而不是输出 `+Inf`。
3. **缓存与压缩**：客户端与服务端都禁用缓存，客户端关闭透明压缩并声明
   `identity` 编码；服务端发送随机数据，避免被压缩后虚高。
4. **连接建立时间**：下载速率窗口不含 DNS/TCP/TLS；首个延迟样本可能包含，
   预热后样本不再包含。
5. **回环测试不代表公网带宽**：`127.0.0.1` 的结果只反映本机协议栈与进程调度能力，
   CLI 会明确打印 `Local Loopback Test`。
6. **单连接结果的含义**：单条 TCP 连接受拥塞控制、窗口和服务器实现影响，
   通常低于链路容量；这是真实结果，不是测量错误。
7. **服务器瓶颈**：结果同时受客户端、服务器 CPU、磁盘（本项目不落盘）、
   反向代理和链路影响。要区分网络瓶颈与服务器瓶颈，请对比多节点结果。

## 如何做重复性与对照验证

建议流程：

```powershell
# 1. 启动本地测试服务器
go run ./cmd/gospeed server

# 2. 固定时长、固定连接数、多次运行
go run ./cmd/gospeed test --duration 10s --connections 1 --json

# 3. 与操作系统工具对照（示例：下载一个大文件 10 次取中位数）
curl.exe -o NUL -w "%{speed_download}\n" http://127.0.0.1:8080/download?bytes=1073741824
```

对照原则：

- 比较同一时间窗口、同一服务器、同一连接数的结果；
- 至少重复 5 次，使用中位数而不是单次最大值；
- 记录 `test_id`、时间戳与 `settings` 快照，保证可审计；
- 当结果与预期差距很大时，先确认瓶颈在客户端、服务器还是链路，
  再讨论测速工具本身是否准确。

## 误差来源（诚实清单）

| 来源 | 影响 | 当前处理 |
| --- | --- | --- |
| 平台时钟分辨率 | 极短传输可能读数为 0 | 返回错误，不编造速率 |
| HTTP 分层开销 | 上传窗口包含一次确认往返 | 明确定义窗口，偏保守 |
| 单连接拥塞控制 | 可能低估链路容量 | 结果标注连接数，v0.2.0 支持多连接 |
| 服务器 CPU / 调度 | 高带宽下可能成为瓶颈 | 文档提示，未来支持多节点对比 |
| 代理与缓存 | 可能改变字节流 | `no-store` + `identity` + 禁用压缩 |
| 回环路径 | 不代表公网 | 明确标记为本地回环测试 |
